### 盘中协议修正（2026-10-19 实测发现）

**0124 预检的应答在盘中走 0x50 推送通道，不是 0x10**。收盘后柜台才回 0x10，
所以这个问题此前一直隐藏着——盘中调用 `precheck()` 会一直等到超时。

对照实验（午间休市时段实测）：

| 实验 | 结果 |
|---|---|
| 登录后静置 15s，不发请求 | 0 推送 → 推送**不是**柜台主动心跳 |
| 发沪市预检 601398 | 1 秒内 2 条 0x50 行情推送，0 条 0x10 应答 |
| 发深市预检 000001 | 1 条 0x50 推送（平安银行，30 字段） |

修复：`TradeConn.recv_msg(accept_push=code)` 同时轮询应答队列与推送队列，
匹配到该股票代码的 0x50 推送即作为预检结果返回（`via_push=True` + `kv` 行情字段）。
修复后 `precheck()` 由「挂死」变为 0.3 秒返回，并首次拿到**盘中实时行情**：

```
601398 工商银行  开8.4700 高8.6300 低8.4400 成交额6.79亿  量20110万股
000001 平安银行  开11.4800 高11.6500 低11.4100 成交额3.98亿 量9253万股
600519 贵州茅台  开1322.50 高1348.60 低1321.00 成交额13.37亿 量250万股
```

### 新增 quote(): 盘中实时行情

`0124 预检` 触发的 0x50 行情推送里, k=v 部分给出开/高/低/成交额/成交量, 但**没有最新价**——
最新价藏在二进制结构区 (float32, 通常 off=194)。新增 `TradeClient.quote(code)`:

```python
{'code': '601398', 'name': '工商银行', 'open': 8.47, 'high': 8.65, 'low': 8.44,
 'last': 8.48, 'volume': 293862980.0, 'amount': 1142580133.0, 'via_push': True}
```

- 验证范围: 主板沪深 9 只 (601398/600519/600036/000001/000651/002594/601899/601288/000858),
  off=194 全部落在 [低,高] 区间 ✅
- **创业板(300xxx)/科创板(688xxx) 记录布局不同**: 整段扫描都找不到落在 [低,高] 的 float32,
  此时 `last=None`(不猜值)
- 收盘后柜台改回 0x10 应答, 无最新价 -> `last=None`
- 实时性验证: 71 秒连采 3 只, 成交额持续递增(601398 +406万 / 600519 +1300万) ✅

### 市价单时段矩阵

| 时段 | 沪/深 市价买 | 市价卖 |
|---|---|---|
| 非交易日(周六) | `该交易时间段不允许市价 OrdType:[1][100101999-010010012]` | 同 |
| 交易日·连续竞价(周一 14:17) | `资金不足：fund_account_id[...]` | `当前账户暂未持仓该证券！` |

即: 非交易日被**时段校验**拦下; 交易日内能通过时段校验进入资金/持仓校验。
(第三格"交易日·收盘后"待补)

### 应答文本可读性

柜台应答 = 二进制结构头 + 业务文本, 直接 `decode('gbk')` 只能看到乱码
(GBK 把二进制头解成了"看起来像汉字"的字符, 连 `isprintable()` 都拦不住)。
新增 `ths_client.client.clean_text()`：用字节级正则 `(?:[¡-þ]{2}){2,}` 找出真正的
中文段, 从**最后一个中文段起点往后取**, 残留二进制折成 `<bin:N>`。0x50 推送是纯文本, 不走此函数。

实盘效果：
```
市价买: 资金不足：fund_account_id[...], branch_id[8337], available_am...
限价买: 资金不足：...
资金查询: 交易市场SX=2.0&SXL=00089&T_WJR=27&...
```
