# 开源与敏感信息处理

本项目涉及真实交易账户，**任何账户信息都不得进入仓库、构建产物或提交历史**。
本文是处理规范，也是自查手册。

---

## 一、什么算敏感信息

| 类别 | 具体 | 风险 |
|---|---|---|
| 账户凭据 | 资金账号、沪/深股东号、户名、交易密码及其任何散列(MD5/SHA) | **极高**——密码散列可离线爆破 |
| 设备标识 | MAC、IMEI、DeviceID、UKey、硬盘/主板序列号、机器 GUID、电脑名 | 高——可长期定位同一台设备/用户 |
| 系统信息 | 本机用户名路径、`C:\Users\xxx`、内网 IP | 中——暴露系统账户名与网络结构 |
| 会话密钥 | 登录后 DES 会话 IV、抓包原文 | 高——可用于重放/仿冒 |
| 业务数据 | 真实委托号、成交记录、持仓明细 | 中——泄露交易习惯 |

**不属于敏感信息**（可公开）：柜台 IP、同花顺产品常量（AppID/接口 GUID/行情字段 ID）、
已零值化的报文模板、券商名称与公开站点列表。

## 二、强制防线（已接入 CI）

| 闸门 | 工具 | 时机 |
|---|---|---|
| ①源码 + 全部 git 历史 | `tools/prepublish_audit.py --history` | CI 的每个 push/PR；发版 build job 第一步 |
| ②构建产物 | `tools/audit_artifacts.py dist/` | CI build job；发版 twine check 之后 |

任一闸门发现敏感信息 → **job 失败 → 不会产出/发布 Release**。

本地自查：

```bash
python tools/prepublish_audit.py            # 只扫当前版本
python tools/prepublish_audit.py --history  # 含全部提交历史（发版前必跑）
python tools/audit_artifacts.py dist/       # 构建产物
```

> 维护规则时注意：`prepublish_audit.py` 的白名单里放的是**产品级常量**
> （同花顺接口 GUID、行情字段 ID、零值化 MAC、示例 IP）。往白名单加东西前，
> 先确认它不是"碰巧像账号的真值"。

## 三、已经踩过的坑

### 1. wheel 会内嵌 README

`pyproject.toml` 的 `readme = "README.md"` 会把整份 README 写进
`*.dist-info/METADATA`。**源码脱敏了，产物里照样是旧账号**——
v0.13.0 第一次发布就踩了这个。所以产物审计是必须的，不能只扫源码。

### 2. 示例代码最容易被忽略

`ths_client/examples/device.json`（真机 IMEI/DID/UKey）、
`check_md5.py`（交易密码 MD5）都是**随 pip 包分发给所有用户**的，
且随包审计常常被跳过。凡是 `examples/` 下的文件，默认按"会被公开"对待。

### 3. 删除文件 ≠ 清除历史

`git rm` 之后 `git show HEAD~1:file` 仍能读到内容，GitHub 上任何人
都能在旧提交里翻到。必须重写历史。

### 4. `git filter-repo` 会误伤

它的密钥脱敏启发式会把 `hosts=[...],`、`info['type'] == 0x50` 这类
普通代码当成密码，改成 `***REMOVED***`。而且 `--replace-text` 只认
`literal:`/`regex:` 行，**传 Python 脚本不会执行**。本项目用
`filter-branch --tree-filter` + 自写脚本。

## 四、历史重写操作手册

⚠️ 破坏性操作，动手前确认已备份、且仓库没有他人协作。

```bash
# 0) 先备份
git branch -f backup/pre-sanitize HEAD

# 1) 写清洗脚本(按需增补替换规则), 放到仓库外
#    示例见下方

# 2) 重写全部提交
FILTER_BRANCH_SQUELCH_WARNING=1 \
  git filter-branch --force \
    --tree-filter 'python /abs/path/sanitize.py' \
    --tag-name-filter cat -- --all

# 3) 删掉 filter-branch 的备份引用并彻底回收对象
git for-each-ref --format='%(refname)' refs/original/ | xargs -r -n1 git update-ref -d
git reflog expire --expire=now --all
git gc --prune=now --aggressive

# 4) 验证
python tools/prepublish_audit.py --history

# 5) 标签要重新指向改写后的等价提交(旧标签对象指向已消失的提交)
git tag -d v0.13.0
NEWHASH=$(git log --format='%H %s' main | grep "原来的提交标题" | head -1 | cut -d' ' -f1)
git tag -a v0.13.0 -m "..." "$NEWHASH"

# 6) 强推(filter-branch 会重写 remote 跟踪引用, 记得补回)
git remote add origin https://github.com/lzy1102/ths_rea.git   # 若被移除
git push --force origin main
git push --force origin v0.13.0
```

清洗脚本模板：

```python
import os
R = [(b'真实账号', b'12345678'), (b'真实设备ID', b'0'*32)]
for dp, dns, fns in os.walk('.'):
    dns[:] = [d for d in dns if d != '.git']
    for fn in fns:
        p = os.path.join(dp, fn)
        if os.path.getsize(p) > 5_000_000: continue
        d = open(p, 'rb').read(); new = d
        for old, rep in R: new = new.replace(old, rep)
        if new != d: open(p, 'wb').write(new)
```

### 重写后必须做的三件事

1. **重新克隆验证**：`git clone` 到临时目录跑 `prepublish_audit.py --history`
2. **通知协作者**：旧 clone 磁盘上仍有原始数据，必须删除重新 clone
3. **重建 Release 产物**：旧 whl/tar.gz 不会被自动替换，需重跑 workflow 覆盖

## 五、提交前自查清单

- [ ] 代码里没有硬编码账户/股东号/密码
- [ ] 配置文件（`local_profile.json`、`sim_profile.json`、`device.json`）在 `.gitignore` 里
- [ ] 抓包目录 `captures/` 未被跟踪
- [ ] 文档示例值都是占位符（`12345678` / `A123456789` / `某某某`）
- [ ] `python tools/prepublish_audit.py --history` 通过
- [ ] `python -m build && python tools/audit_artifacts.py dist/` 通过

## 六、残留说明

- **提交作者邮箱**：改写历史时若使用默认设置，作者信息保留。若需彻底更换邮箱，
  需额外做 author 重写（会让所有提交显示新作者）。
- **GitHub 缓存**：无 PR/fork 的仓库在强推后不会有历史快照残留；若有 fork，
  对方仓库里仍保留旧对象，需自行清理。
