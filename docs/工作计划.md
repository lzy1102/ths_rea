# 工作计划 · ths-trade-client

> 同花顺柜台交易协议纯 Python 客户端 —— 路线图与任务清单
> 更新: 2026-10-16 · 协议细节见 [下单逆向进展-3.md](下单逆向进展-3.md)

## 一、项目目标

1. **协议复刻**: 纯 Python 实现同花顺柜台交易协议（登录/查询/委托），不依赖客户端
2. **可分发**: pip 安装包（`ths-trade-client`），供量化框架/其他程序直接调用
3. **可维护**: 协议随客户端版本变化时，有标准化抓包→模板→验证的流程

## 三、路线图

### 阶段 1 · 交易闭环补全（P0）

- [ ] **1.1 深市市价委托**
  - 方法: 挂 `tools/deep_capture.py` → 真客户端下深市测试单（如 000001）→ 解密报文 → 模板化
  - 验收: 深市市价单实盘到达资金检查（同沪市标准）
- [ ] **1.2 限价委托（沪/深）**
  - 方法: 同上，抓真客户端限价单报文；确认 `wtjg=<价>` 与市价差异（sjwt 字段缺省行为）
  - 验收: 限价单实盘提交成功（可先用高价/低价避开成交）
- [ ] **1.3 撤单**
  - 方法: 真客户端挂一笔远离市价的限价单 → 撤单 → 抓包；确认撤单标识（合同编号/委托号字段）
  - 验收: API `cancel(order_id)` 实盘撤单成功
- [ ] **1.4 委托/成交/持仓/资金 查询 API**
  - 已有素材: 0126/0326/0226/0520/0526 报文（已捕获可解密）+ 日志类型表（601/602/603/605/608）
  - 验收: `query_orders()/query_trades()/query_positions()/query_balance()` 返回结构化 dict
  - 注: 部分应答含加密块（`xd_func=`），需单独解密（见 3.3）
- [x] **1.5a 沪市市价卖出（0321）—— ✅ 协议层打通 (2026-10-16)**
  - 真客户端抓包实测: cmd=03 21 (内部03 01); 二进制价格float=-1.0(同买);
    文本差异: wtjg=<保护限价>(买单为-1) / workid=9(买2) / menuid=472(买471)
  - 实测: 收盘前真客户端卖单 → "当前账户暂未持仓该证券！"(持仓检查);
    我方客户端卖单(收盘后) → "不在引擎接受订单的时间范围！[-013070001]"(引擎时间检查)
  - 实现: trade_msg.build_sell_sh_sjwt() + client.sell_market()
  - 模板: captures/sh_order/sell_0321_624.bin
- [ ] **1.5b 限价卖出 + 深市卖出**（需交易时段抓包）
- [ ] **1.5c 撤单**（需交易时段挂限价单后撤单抓包）

### 阶段 2 · 会话健壮性（P1）

- [ ] **2.1 成交回报/服务端推送处理**
  - 问题: 会话期间服务端主动推帧（0x10 大帧）；现为请求-应答模型
  - 方案: 后台读线程 + 帧路由（应答/推送分流），回调接口 `on_push`
- [ ] **2.2 心跳与断线重连**
  - 方法: 观察真客户端空闲期消息规律（0f29/0526 周期?）→ 复刻；断线自动 login+bootstrap 重建
  - 验收: 挂机 1 小时会话不掉/掉线自动恢复
- [ ] **2.3 多柜台节点与故障切换**
  - 现状: 柜台 IP 随券商调度变化（已见 114.141.180.27 / 122.224.106.10 / 60.12.226.4）
  - 方案: 节点列表配置 + 连接失败轮换；研究同花顺节点发现（DNSTest.xml/域名）
- [ ] **2.4 登录模板跨机器适配**
  - 问题: 登录明文含硬件指纹（hardwarecode/macinfo/guid）
  - 方案: ①验证服务端是否校验（换机器实测）②否则写 `tools/capture_login.py` 一键重抓模板
- [ ] **2.5 错误处理规范化**
  - 整理服务端错误文本表（资金不足/帐户无效/代码不存在/价格错误/交易信息表…）→ 异常类型

### 阶段 3 · 易用性与质量（P2）

- [ ] **3.1 应答结构化解析**

- [ ] **3.3 文档**

- [ ] **3.4 框架接入示例**

## 五、风险与依赖

| 风险 | 说明 | 对策 |
|---|---|---|
| 协议随版本失效 | 客户端升级可能改帧/字段/加密 | 抓包→模板流程标准化（tools 已就绪） |
| 账号资金 | 实盘验证需要资金（当前账户不足, 委托只能到资金检查） | 小额验证；资金检查即视为协议通过 |
| 合规 | 程序化交易需遵守券商/监管要求 | 仅自有账户；控制频率；保留人工确认 |
| 敏感数据 | 抓包含账号/股东号/密钥 | captures/ 已 .gitignore；文档不落真实密钥 |
| 深市/限价模板缺失 | 需要真客户端实际操作一次抓包 | 用户配合下单即可（已验证流程） |
| 卖出验证需持仓 | 卖出需账户持有股票才能真实验证 | 用有持仓股票小额卖出（顺便变现）；无持仓则以持仓检查拒绝为通过标准 |

## 六、如何继续抓包（操作手册）

```bash
# 1) 抓报文构建/密钥 (自动挂载, 可捕获所有进出消息明文)
python tools/deep_capture.py <xiadan_pid> 1800     # 输出 captures/svc_cap/

# 2) 抓登录全过程 (进程启动前挂载, spawn 方式最稳)
python tools/login_watch.py <pid> 600              # 输出 captures/login_watch_raw.bin

# 3) 分析: 解密 send_content_*.bin → 提炼模板 → 存 ths_client/data/
#    参考本轮: svc_cap/ → sh_tpl/ → trade_msg.py 模板内嵌
```

**模板化标准流程**: 真客户端操作 → 捕获内容 → 用会话IV解密 → 定位差异字段 →
作为模板内嵌（base64）→ 补丁函数（sess/tick/seq/md5）→ 实盘验证。
