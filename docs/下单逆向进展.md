## 1. 加壳与保护分析结论

| 模块 | 保护 | 处理 |
|---|---|---|
| xiadan.exe (86MB, PE32) | 外层小壳 + **VMProtect**（`.vmp0/.vmp1` + .text 磁盘加密、运行时按需解密） | PE-sieve 内存 dump 成功 |
| hexin.exe (17MB) | **UPX**（标准） | `upx -d` 脱壳成功 → `D:\ths_win_extract\unpacked\hexin_upx.exe` |
| embeddedtrade.dll | VMProtect | 待处理 |
| device_fingerprint.dll / weituonew.exe | 无壳 | 可直接静态分析 |

**重要现象**: VMProtect 采用**懒解密**——只有被执行过的函数才会在内存里解密成可读代码。
- dump 里 `.text` 大部分仍是密文，但执行过的部分是真代码（用字符串引用验证：`xd_mairu` 命中）
- 未执行到的功能（登录请求构建等）依然找不到引用 → 需要触发执行后才能 dump 出来

## 3. 已回收的下单协议证据（关键）

### 3.1 下单报文格式（反汇编确认）

函数 `fcn.00f4ad00`（dump VA `0x00f4ad00`，RVA `0x65ad00`）构建下单包：

```c
if (arg5 != 0) cmd = "xd_mairu";   // 买入
else           cmd = "xd_maichu";  // 卖出
sprintf(pkt,
  "cmd=%s\n"
  "code=%s\n"
  "price=%s\n"
  "amount=%s\n"
  "lock=%s\n"
  "relmarket=%s\n"
  "dzh=1\n"
  "relmarket=%d\n"
  "userkey=%s\n",
  cmd, code, ..., ...);
```

- 报文类型: **换行分隔 key=value 文本协议**（与旧 THS 委托协议一致）
- 关键字段: `cmd` / `code` / `price` / `amount` / `lock`（锁价）/ `relmarket`（关联市场）/ `dzh`（多账户?）/ `userkey`（会话密钥）
- 命令字: `xd_mairu`(买入) `xd_maichu`(卖出) `xd_dmdm` `cmd_qu_zijin`(查资金)
- 内部命令: `tjdd_upload_wt` `tjdd_chedan` `tjdd_order` `tjdd_cx_dd` `tjdd_cx_gpxx` `tjdd_extend` `tjdd_change`

### 3.2 订单字段名池（dump 0x30c4400 附近，GBK）

`preuserkey` / `userkey_list` / `baseprice` / `htbh`(合同编号) / `czlb`(操作类别) / `hui zong_htbh` / `hui zong_date_tradedir` / `rzrq_cx...` / 买一价/卖一价 等

### 3.3 登录协议模板（还在密文区，来自磁盘静态串）

```
%s/verify2?reqtype=do_rsa&type=get_pubkey      # 取 RSA 公钥
%s/verify2?reqtype=unified_login&account=%s&passwd=%s&rsa_version=%s&imei=%s&ta_appid=2022021835675725
%s/verify2?...&uver=%s&ttype=%s / ...&msg=1&ta_appid=%s
```

### 3.4 传输与辅助事实

- xiadan 使用 **WININET + WS2_32**（可被系统代理/Fiddler/ mitmproxy 抓包）
- 本地监听: `127.0.0.1:<随机端口>`（本次 57867）；嵌入页 JS 调用 `http://127.0.0.1:8086/auth?`（8086 由其他组件提供，未在 xiadan 监听）
- 运行期 inline hook 3 处、VMProtect patch 区域位于 .vmp0
